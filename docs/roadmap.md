# Short-term porting roadmap

1. **Maintain repeatable code generation.** The [first Windows executable](builds.md#build-0004--first-windows-x64-executable) established that the verified `4156084C/02619995` XEX can generate and link. Keep address-specific hints reviewable and record the evidence for each one. Check indirect calls and jump tables as startup exercises more code.
2. **Preserve the first Windows menu boot.** [Build 0016](builds.md#build-0016--first-confirmed-windows-main-menu) reached the main menu and the Campaign brightness prompt. Its source snapshot is preserved on `milestone/first-pc-boot-b16`.
3. **Stabilize one playable PC segment.** Clear the campaign crashes and verify a checkpoint transition. Compare input, UE3 file loading, Bink playback, FMOD audio, Scaleform UI, and PhysX against the Xbox 360 version. Record visual issues that affect play, including mission selector text corruption.
4. **Bring up the Renut renderer on deko3d.** [Build-29](builds.md#build-29--validate-and-submit-the-switch-startup-shader-pack) reached a visible, navigable menu with missing interface elements and background using the SDK's deko3d renderer. The first Switch boot is preserved as `milestone/first-switch-boot`. [Build-30](builds.md#build-30--coarsen-physical-memory-backing-and-add-character-selection-shaders) passed character selection and reached gameplay with a black scene behind the overlay. [Build-31](builds.md#build-31--render-and-resolve-packed-and-hdr-color-surfaces-on-switch) adds packed and HDR targets and resolves. Verify the full menu and visible gameplay on hardware and compare the first rendered scenes with the Windows build.
5. **Profile and publish reproducible UE3 findings.** Record build commands, regressions, and before-and-after checks as each milestone lands. Once the first segment works on Switch, measure frame times, CPU/GPU load, and memory on the same route with cold and warm shader caches at known clocks and resolution.

## Switch deko3d preflight

- **Runtime and toolchain.** The [Gears of War 2 reference](https://github.com/VasilkovND/gears2-nx/tree/c202b045cce00c96b040b095eb8e5250c7c83b59) uses [ReXGlue for Horizon at `f961303fe3c6e3a90905b379ff4bf3de9a35a757`](https://github.com/nx-mod/rexglue-sdk-nx/tree/f961303fe3c6e3a90905b379ff4bf3de9a35a757). Its CMake option `REXGLUE_SWITCH_DEKO3D` enables a title-provided renderer. WFC needs its own application, Xenos command handling, shader lookup, and NRO packaging.
- **Windows toolchain check.** Local devkitPro packages were recovered from the LB2NX setup after package downloads returned HTTP 403. The checkout uses `out/deps/switch-toolchain/opt/devkitpro` as `DEVKITPRO` for this check. The package names and SHA-256 values are in `out/deps/switch-toolchain/packages.json`. GCC 16.1.0 linked a minimal ARM64 program with libnx 4.12.0 and deko3d 0.5.0. UAM 1.1.0 compiled a test fragment shader to DKSH, and switch-tools 1.13.1 packed the ELF and shader into a local NRO. The probe has yet to run on console hardware.
- **Cooked packages.** On the XEX revision used for [build-22](builds.md#build-22--register-the-decepticon-campaign-callback), the sampled Xbox 360 shader-related packages carry big-endian package version 511 and licensee version 144. LZO1X decompressed 305 blocks to their declared sizes across `ENV_AllShader_p.xxx`, `TR_AllShader_p.xxx`, `ENV_NEU_VariantShaders_p.xxx`, and `ENV_ORB_D1_Shader_p.xxx`. The Gears 2 extractor expects package version 575 and XMem-framed LZX. WFC still needs a validated shader inventory and package parser.
- **First offline shader translation.** The Windows ReXGlue `XESH` cache contained 136 vertex and 300 pixel shader records. Three complete programs matched bytes in the mapped XEX at `0x823E15E8`, `0x823E1528`, and `0x823E027C`. The last is a 36-byte pixel program with cache key `a4a965c189287b99`. The pinned Gears 2 host converter translated it to HLSL with a synthetic test header, and [DXC v1.8.2505.1](https://github.com/microsoft/DirectXShaderCompiler/releases/tag/v1.8.2505.1) compiled a 2,100-byte SPIR-V fragment module. The Horizon SDK's pinned [SPIRV-Cross revision](https://github.com/KhronosGroup/SPIRV-Cross/tree/f11ba9f0b21ba8fc15153d50a2a1ae31ab1cf8f7) emitted GLSL 450, and UAM 1.1.0 compiled it with `uam -s frag -o sample.dksh sample.frag`. The local 768-byte output had DKSH magic and SHA-256 `abb6871f957ae37ce1143739578469c23975dfc3bf9fd666f44de01358b6fc7b`. This probe sampled one shader with default specialization. Runtime bindings, Renut's shader path and on-console output remain to be verified.

## Direct3D entry points for Renut

These static findings use the [supported WFC executable hash](../UE3_Xbox360_Switch_References.md#war-for-cybertron-discs-and-packages) and the generated registration table from build-22. The XEX static-library header (`0x000200FF`, file offset `0x2934`) records `D3D9LTCG`, `D3DX9` and `XGRAPHC` version `2.0.9328.0`. The import headers also identify `xam.xex` and `xboxkrnl.exe` at `2.0.9328.0`. See the [ReXGlue XEX header definitions](https://github.com/nx-mod/rexglue-sdk-nx/blob/f961303fe3c6e3a90905b379ff4bf3de9a35a757/include/rex/system/util/xex2_info.h).

| WFC function | Evidence | Relevance to Renut |
| --- | --- | --- |
| `0x82480360`, device creation | Allocates `0x5F80` bytes, aligns the device to 128 bytes and clears `0x5F00` bytes. Saves the output pointer from `r8` and stores the device through it. Calls `0x8249ABE8` at `0x82480488` on the hardware path. | The device size and output parameter differ from Alice's. Verify the live ABI before replacing it. |
| `0x8249ABE8`, hardware initialization | Calls `VdInitializeEngines` at `0x8249AC38`, sets the interrupt callback at `0x8249AC7C`, and calls the ring setup at `0x8249ACD8` with the device in `r3`. | Provides anchors for startup and synchronization. |
| `0x824969A8`, ring setup | Calls `VdInitializeRingBuffer` at `0x82496BA8`. | Anchor for the guest command ring. |
| `0x82496340`, submission candidate | Reads device fields at `+0x2A90` and `+0x2A9C`, passes the second field minus two to `0x82496440`, sets bit `0x02` at `+0x2ABD`, and returns the pointer at `+0x30`. | Matches the shape of Alice's KickOff. Its callee compares the requested fence and the dereferenced completion counter relative to the same tag, and can call back into submission. |
| `0x8248E850`, swap | The only direct caller of `VdSwap` in the guest code, at `0x8248EB4C`. Copies 24 bytes from the second argument at `+0x1C`, increments the count at device `+0x4180`, and updates the ring pointer at `+0x30`. | Swap and ring fields can be tracked independently. Alice's swap count is at `+0x41C8`. |
| `0x82486C90`, pixel shader registration candidate | Clears 40 bytes from the object in `r3`, stores type 7 and reference count 1, then stores the address in `r4` at `+0x18`. One game call site is `0x829D312C`. | Matches the object setup in Alice's `XGRegisterPixelShader`. Capture the physical shader bytes and compare them to the PC shader cache. |
| `0x82486F78` and `0x82486FB8`, vertex shader registration candidates | The first prepares the container at `+0x368`. The second clears the prefix up to that offset and sets type 6, reference count 1 and the physical shader address at `+0x20`. The game calls both at `0x829D2FBC` and `0x829D2FEC`. | These are candidates for tracing WFC's vertex shader container and microcode together. |
| `0x8248FEF8`, `0x824903E8`, `0x824909A0`, `0x82490D90`, draw candidates | Write type-3 PM4 draw packets with opcode `0x22` at `0x8249027C`, `0x824907CC`, `0x82490C70` and `0x824910CC`. | Correlate the two- and four-word packet payloads with a PC frame trace before assigning the draw APIs and hook arguments. |

To reproduce, verify the XEX hash and generate the desktop sources. Search the generated `wfc_recomp.*.cpp` units for `__imp__VdSwap(ctx, base)`, `__imp__VdInitializeEngines(ctx, base)` and `__imp__VdInitializeRingBuffer(ctx, base)`. Use the containing `DEFINE_REX_FUNC` and the recorded link register to recover each entry point and call site. Cross-check by disassembling the [mapped PE](builds.md#branch-target-analysis-build-3) and following direct PowerPC branches to the import thunks. The first PC renderer trace should confirm device creation, initialization, and swap counts, then identify draw, resolve and shader-registration paths with frame captures.
